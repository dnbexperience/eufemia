## Description

The design tokens are synchronized from Figma with the "Design Tokens" GitHub Action and converted to CSS variables with the `make-properties` script. We currently generate color and radius tokens. Typography is skipped.

## Overview

- Design tokens are synchronized from Figma by a GitHub Action, which opens a draft pull request for review.
- We generate color tokens and radius values. Typography aliases and string values are skipped for now.
- We export Foundation colors, plus light and dark brand token modes for DNB and Sbanken (Carnegie is light-only for now)

## How to update

### 1. Run the "Design Tokens" workflow

1. Open [**Actions → Design Tokens**](https://github.com/dnbexperience/eufemia/actions/workflows/tokens-sync.yml), then select **Run workflow** on `main`.
1. The workflow runs in three steps:
   1. **Fetch:** It reads the Figma variables with the [variables REST API](https://developers.figma.com/docs/rest-api/variables-endpoints/), writes one `*.tokens.json` file per mode of the fetched collections, and commits them to a draft pull request. Changes in Figma, such as a new mode or collection, do not make this step fail. Variables that cannot be converted are skipped, and the workflow lists them in a pull request comment.
   1. **Verify:** It checks that the exports the themes are generated from are there and can be converted to CSS, such as variable names and the collections tokens point to. Exports that no theme uses are ignored.
   1. **Generate:** It regenerates the CSS files and their test snapshots, builds the library and Portal, updates the visual snapshots and pushes the result to the same pull request.
1. If the verify or generate step fails, the workflow comments on the pull request. The fetched exports stay in the pull request, so you can see what changed in Figma. Existing reviewer commits are preserved. If Figma and the pull request are already synchronized, it reports that no changes were found.
1. Review the token values, removals and visual snapshots before marking the pull request ready.
1. Review and (squash) merge the pull request.

The workflow is the only way to update the exports, so every update has the same format. The REST API differs from a manual "Export Modes" in Figma: it only returns the foundation colors the file uses, includes `hiddenFromPublishing`, and writes scopes such as `STROKE_COLOR` instead of `STROKE`.

The workflow needs the repository secret `FIGMA_TOKEN` (a personal access token with the `file_variables:read` scope) and the repository variable `FIGMA_TOKENS_FILE` (the key of the "💻 Eufemia - Web" file). The Figma variables API is only available to Enterprise organizations.

### Fetched collections and files

The fetched collections are listed in `TOKEN_COLLECTIONS` (`packages/dnb-eufemia/scripts/figma/tasks/tokensExtractor.ts`). Each mode is written to `packages/dnb-eufemia/src/style/themes/figma` with a file name made from the mode name, such as `dnbeiendom-light (test)` → `dnbeiendom-light-test.tokens.json`:

- "Foundation" collection "colors" (`color.tokens.json`)
- "💻 Eufemia - Web" collection "brand", one file per mode in the `brand` subfolder, such as `brand/dnb-light.tokens.json`

The exports the themes need are listed in `DESIGN_TOKEN_FILES` and `FOUNDATION_TOKEN_FILES` (`packages/dnb-eufemia/scripts/prebuild/tasks/makePropertiesFile.ts`). The verify step checks them. To use a new mode in a theme, add it there.

Each brand-mode export is a complete snapshot of the collection, so light and dark files also contain shared font and radius values. The generator produces one typography scale per brand from the light export. Dark mode does not change font sizes or line heights.

### 2. Generate CSS files

The CSS files are automatically generated during the "Prebuild" step by the `makePropertiesFile.ts` script (`packages/dnb-eufemia/scripts/prebuild/tasks/makePropertiesFile.ts`).

#### Generate locally (manual)

To generate the files manually you can run the command `yarn workspace @dnb/eufemia make-properties`.

To fetch the tokens from Figma locally, add `FIGMA_TOKEN` and `FIGMA_TOKENS_FILE` to your `.env` file and run `yarn workspace @dnb/eufemia figma:tokens`. Then run `yarn workspace @dnb/eufemia figma:tokens:verify` to check the exports.

## Naming conventions/transforms

Since Figma has different rules and limitations than CSS we have established some naming conventions to avoid errors.

- only use alphanumeric characters. (a-z and 0-9)
- Variables are not case-sensitive. (`onDark` and `ondark` are considered the same variable)
- We use dashes (`-`) to separate groups and words.

### Transforms

During the CSS generation, Figma variables are converted to lower case. And groups are separated by dashes (`-`).

Only characters `a-z` `A-Z` `0-9`. and `-` are supported. Any unsupported characters will throw an error.

We also add the prefix `token` to the variables from the `Brand` collection.

### Example

Figma variable: `Color/Dimmer/Action-Pressed-Subtle-OnDark`

CSS variable: `--token-color-dimmer-action-pressed-subtle-ondark`

### Potential issues

Even following all the rules, we still risk naming overlap since groups and words use the same separator in CSS `color/action/pressed` and `color/action-pressed` would map to the same variable.

But these will at least be caught on build.
