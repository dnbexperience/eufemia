The documentation is written in enhanced Markdown, called MDX. It allows us to import other Markdown files along with React components and JavaScript logic.

## Property usage guidance

When documenting a customization property, explain its intended use, the preferred default, and when DNB UX approval is needed. Follow the [intended use and customization guidance](/uilib/usage/customisation/component-properties/#intended-use-and-customization).

Keep the prop description and TypeScript JSDoc aligned so the same guidance appears in the Portal and editor. Identify technical customization examples clearly when they go beyond the component's intended patterns.

Properties pages that only document API parameters or translations can set `hidePropertiesUsage: true` in their frontmatter to omit the component customization note from the Portal and generated Markdown.

## Sidebar menu placement

Pages follow their URL hierarchy in the sidebar by default. To display a page immediately before another menu item while keeping its URL unchanged, provide the target item's absolute slug:

```yaml
sidebarMenuPlacement: '/uilib/components'
```

The page is removed from its URL-derived location and inserted immediately before the target. Use this for overview pages that should be siblings of the section they describe.

To render a horizontal separator immediately before the page, add:

```yaml
sidebarMenuDividerBefore: true
```

This can be used independently or together with `sidebarMenuPlacement`.

Use `sidebarMenu` to move a page into the Portal's curated navigation:

```yaml
sidebarMenu:
  parent: uilib/foundations-menu
  title: Layout & spacing
  order: 6
  static: false
```

- `parent` identifies the configured root that owns the page.
- `title` overrides the page title in the menu.
- `icon` selects a registered sidebar graphic when the item needs one.
- `order` controls the item's position within its parent.
- `static: true` renders a non-collapsible group. Use `false` for a page that also owns child pages.
- `hideStatus` hides the page's status badge in the sidebar.

A page can define a top-level menu with `root: true`. `id` and `path` can give a synthetic root its own identity, while `includePageAs`, `pageIcon`, and `pageOrder` add the source page itself as a child link:

```yaml
sidebarMenu:
  id: uilib-guides-menu
  path: uilib/guides-menu
  title: Guides
  icon: lightbulb
  order: 7
  root: true
  includePageAs: Platform comparison
  pageOrder: 7
```

For a page that defines a synthetic root menu, `pageParent` places only the page link under another menu item while leaving the synthetic tree in place:

```yaml
sidebarMenu:
  root: true
  includePageAs: UI library
  pageParent: uilib/about-the-lib
  pageOrder: 2
```

## Handling themes

If you need to show some documentation only for when a certain theme is selected, you can do so:

```md
<VisibilityByTheme visible="eiendom">

## Eiendom examples

Text

<SpecialExample />

</VisibilityByTheme>
```

### Link to a specific theme

You can add a parameter called `eufemia-theme` to a url:

```md
[Relative](/uilib/components/badge/demos/?eufemia-theme=sbanken)
Absolute: https://eufemia.dnb.no/uilib/components/badge/demos/?eufemia-theme=sbanken
```

It will change and set the currently used theme once the user visits the related page.

## Printing

Portal pages use the shared plain print layout, including fullscreen
documentation. Navigation and editing tools are hidden, and the page path
and version appear after the content.

A page that demonstrates its own print layout can set `printLayout: custom`
in its frontmatter. It then owns paper colors, layout and footer behavior.
Use this for document previews and dedicated print-style fixtures,
independently of the `fullscreen` setting.

## Page table of contents

Portal builds a table of contents from visible documentation headings and their anchor links. Headings inside component demos are excluded. Keep headings descriptive and their anchor ids unique, including when importing MDX partials.

Pages without section headings omit the table of contents. Otherwise, the page title is included as the first link, using TableOfContent.Data's includeH1 option. It links back to the introduction and becomes current before the first section. The configured tocDepth still counts section levels below H1.

The static HTML includes the table of contents and its heading data alongside the page content. Hydration reuses that data, then tracks headings that are added, removed or changed in the browser. The mobile disclosure and desktop links are styled for the viewport before hydration.

Portal disables heading-list replacement animation with animateChanges set to false. Applications can opt in through TableOfContent.Root or TableOfContent.Data; see the [extension documentation](/uilib/extensions/table-of-content/).

The skip link moves focus to the main content, including its title and tabs. On desktop, the outline follows the article in the reading and keyboard order. On mobile, the disclosure comes before the article. The outline uses the shared native scrollbar sizing. Scrolling inside an overflowing desktop outline stays within its list; a short outline allows the page to scroll.

The table of contents is sticky on wide screens and a disclosure above the content on smaller screens. On narrow screens it initially shows up to 10 links, including the page title, with a translated “Show all” button that disappears after revealing the remaining links. The component's maxVisibleItems property configures this limit. Browser find-in-page also reveals the full list when it matches a hidden link, where hidden="until-found" is supported. Its open or closed choice is stored in session storage with expandedStorageKey, so it survives page navigation, reloads and viewport changes within the same tab. The saved state is restored before first paint. It is hidden in focus mode and fullscreen pages.

Use frontmatter to adjust individual pages:

```md
---
hideToc: true
tocDepth: 1
---
```

Use hideToc to hide the navigation and tocDepth to limit its visible heading levels. The default depth is two levels below the page title. A tab page inherits these settings from its parent unless it supplies its own value.

## Language

Write the documentation in American English, such as _color_, _behavior_, _canceled_, and _customize_.

Keep the original spelling in:

- Release notes and the changelog.
- URLs, file paths, and public names, such as `/uilib/usage/customisation/`.
- Names and titles of external sources.

Translations follow their locale. See [Locale support](/contribute/getting-started/making-changes#locale-support).
