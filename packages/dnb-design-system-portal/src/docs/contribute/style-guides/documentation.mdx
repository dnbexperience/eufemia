The documentation is written in enhanced Markdown, called MDX. It allows us to import other Markdown files along with React components and JavaScript logic.

## Sidebar navigation

Navigation is defined in each MDX document, independently of its URL. There is no separate menu configuration file. Use the parent document's slug to place a page:

```yaml
title: Installation
navigation:
  parent: web/get-started
  order: 1
```

A menu-only accordion has no content or route:

```yaml
title: Get started
route: false
navigation:
  parent: web
  kind: group
  order: 1
```

Use `kind: category` for a static category heading and `kind: placeholder` for disabled “To do” entries. A platform definition uses `kind: platform` and `platform: web`, `ios`, or `android`. Shared definitions have no platform parent and appear above the platform dropdown.

Use icons only for top-level shared entries and top-level entries within a platform. Nested pages and accordions should not declare an `icon`.

Published pages with a title must declare `navigation`, or explicitly use `navigation.hidden: true` when they should not appear in the sidebar. The navigation checks reject missing definitions and source files under the retired `src/docs/uilib/` directory. New web documentation belongs in `src/docs/web/`, including pages brought in from older branches.

When an existing content page also has children, the accordion opens without navigating. Its content remains available as the first child. Give that child a name that describes what the page offers with `navigation.pageTitle`, such as “Quick start” or “Using typography”, rather than repeating the accordion name with “overview”. `navigation.title` can shorten the menu label without changing the page heading. Use `navigation.hidden: true` to keep a page out of the sidebar.

## Moving pages

Use meaningful MDX filenames, not `index.mdx`. The home document is `home.mdx` with `slug: /`. When moving a page, retain its old URL in `redirect_from`:

```yaml
redirect_from:
  - /uilib/getting-started
```

Aliases preserve query strings and fragments. A section definition can declare `legacyPrefixes` for all descendant routes, including TSX demonstration pages. `legacyFragments` maps old section anchors to a new page when content is split.

## Handling themes

If you need to show some documentation only for when a certain theme is selected, you can do so:

```md
<VisibilityByTheme visible="eiendom">

## Eiendom examples

Text

<SpecialExample />

</VisibilityByTheme>
```

### Link to a specific theme

You can add a parameter called `eufemia-theme` to a url:

```md
[Relative](/web/components/badge/demos/?eufemia-theme=sbanken)
Absolute: https://eufemia.dnb.no/web/components/badge/demos/?eufemia-theme=sbanken
```

It will change and set the currently used theme once the user visits the related page.

## Language

Write the documentation in American English, such as _color_, _behavior_, _canceled_, and _customize_.

Keep the original spelling in:

- Release notes and the changelog.
- URLs, file paths, and public names, such as `/web/usage/customisation/`.
- Names and titles of external sources.

Translations follow their locale. See [Locale support](/contribute/getting-started/making-changes#locale-support).
