### Icon button

**Use buttons with visible text by default.** Only use an icon-only button when the action and what it affects are immediately clear to your users, without a tooltip. If there is any doubt, keep the text label.

#### Choose an icon that fits the context

Use an existing [Eufemia icon](/icons) and keep its meaning consistent throughout your application. Even in the contexts below, only omit the text label if the action and its scope are unambiguous to your users.

|                   Icon                   | Action | Context to check                    |
| :--------------------------------------: | ------ | ----------------------------------- |
| <IconPrimary icon="close" aria-hidden /> | Close  | In the dialog or panel it closes.   |
| <IconPrimary icon="trash" aria-hidden /> | Delete | Beside the attachment it deletes.   |
| <IconPrimary icon="loupe" aria-hidden /> | Search | Beside a labeled search field.      |
| <IconPrimary icon="edit" aria-hidden />  | Edit   | In the row of the item it edits.    |
|  <IconPrimary icon="add" aria-hidden />  | Add    | In a list that shows what is added. |

#### Use visible text when

- **The action is important or difficult to undo**, such as "Send payment" or "Delete account". A trash icon does not explain the scope of a deletion.
- **The icon could mean several things.** A plus could mean add an item, create an account, or zoom in. Use a label such as "Add account".
- **People need a tooltip to understand the action.** Tooltips can help, but should not be the only explanation, especially on touch screens.

Limited space, including on smaller screens, is not enough reason to remove a text label.

#### Name the action

Every icon-only button needs an accessible name. Describe the action, such as "Delete invoice.pdf", rather than the shape, such as "Trash icon".

Set `aria-label` and add a matching `tooltip` for hover and keyboard focus. A `tooltip` alone does not provide an accessible name in Eufemia.

```tsx
<Button icon="close" aria-label="Close" tooltip="Close" />
```

Alternatively, `title` supplies the accessible name automatically for icon-only buttons.

The labels above the buttons identify the sizes and states.

### Sizes

Use `default` or `large` for primary and secondary buttons. Icon-only buttons also support `small` and `medium`. See [Variants and sizes](/uilib/components/button/#variants-and-sizes) for the size comparisons.

### Anchor button

Set `href` when navigation needs the visual emphasis of a button. Button renders an anchor element in this case. Prefer [Anchor](/uilib/components/anchor) for ordinary links.

<ButtonAnchor />

### Disabled buttons

Set `disabled` to make an action unavailable. Prefer keeping actions available where possible. A disabled button alone does not explain what the user needs to do next.

<ButtonDisabled />

### Error state

Set `status="error"` to indicate an error state. When an action fails, also explain the problem and how to recover. A color change alone is not enough.

<ButtonErrorState />

### Button on dark surface

Use [Section](/uilib/components/section/demos/#dark-surface) or [Theme.Context](/uilib/usage/customisation/theming/theme#surface-property) with `surface="dark"` to provide dark surface context to supporting components.

<ButtonOnDarkSurface />

### Custom button content

Use `customContent` when the standard label and icon do not cover the content you need. You are responsible for aligning custom content.

<ButtonCustomContent />

### Button with custom SVG

A custom SVG can be part of the button's children. Give meaningful graphics an accessible name and hide decorative graphics from assistive technology. The button still needs a meaningful accessible name.
