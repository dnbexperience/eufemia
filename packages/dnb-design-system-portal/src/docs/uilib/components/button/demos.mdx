### Icon button

Use icon-only buttons for familiar actions in compact areas, such as toolbars and list rows. People should understand the action and what it affects before selecting the button.

#### Choose an icon that fits the context

Use an existing [Eufemia icon](/icons) and keep its meaning consistent throughout your application. These examples depend on context, not just the icon:

|                   Icon                   | Action | Icon-only can work when…            |
| :--------------------------------------: | ------ | ----------------------------------- |
| <IconPrimary icon="close" aria-hidden /> | Close  | In the dialog or panel it closes.   |
| <IconPrimary icon="trash" aria-hidden /> | Delete | Beside the attachment it deletes.   |
| <IconPrimary icon="loupe" aria-hidden /> | Search | Beside a labeled search field.      |
| <IconPrimary icon="edit" aria-hidden />  | Edit   | In the row of the item it edits.    |
|  <IconPrimary icon="add" aria-hidden />  | Add    | In a list that shows what is added. |

#### Use visible text when

- **The action is important or difficult to undo**, such as "Send payment" or "Delete account". A trash icon does not explain the scope of a deletion.
- **The icon could mean several things.** A plus could mean add an item, create an account, or zoom in. Use a label such as "Add account".
- **People need a tooltip to understand the action.** Tooltips can help, but should not be the only explanation, especially on touch screens.

Do not remove a useful text label just to fit a smaller screen.

#### Name the action

Every icon-only button needs an accessible name. Describe the action, such as "Delete invoice.pdf", rather than the shape, such as "Trash icon".

Set `aria-label` and add a matching `tooltip` for hover and keyboard focus. A `tooltip` alone does not provide an accessible name in Eufemia.

```tsx
<Button icon="close" aria-label="Close" tooltip="Close" />
```

Alternatively, `title` supplies the accessible name automatically for icon-only buttons.
