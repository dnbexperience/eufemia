Every [Component](/uilib/components) has properties to support different use cases. Each component's Properties page describes the available options, such as the [Button properties](/uilib/components/button/properties).

## Intended use and customization

Start with the component's documented patterns and defaults. The demos show intended usage, but cannot cover every valid use case.

Some properties support specific integrations or give Eufemia components flexibility internally. Their availability does not mean every possible customization is a recommended design. Technical customization examples illustrate what the API allows.

Follow the usage guidance beside each property. Changes to a component's established appearance, content structure, or interaction pattern beyond the documented patterns need a use case approved by DNB UX. Properties marked internal are intended for Eufemia's own integrations.

The same guidance applies when configuring components through nested props, Provider, or custom CSS.

## Naming

Both the properties- and event names should use **camelCase** to support a universal [naming convention](/contribute/style-guides/naming).
