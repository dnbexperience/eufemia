## Events

Search components use the events of their underlying components. All support `onFocus`, `onBlur`, `onClear`, and `onSubmit`.

### Search.Input

Use `onChange` to receive query changes and `onSubmit` to handle Enter. Both receive an object containing `value` and `event`.

Inside a form, Enter also submits the form, as in any native search input. Call `event.preventDefault()` in `onSubmit` to handle the query without submitting the form. Search.Autocomplete and Search.Panel do not submit a surrounding form.

See [Input events](/web/components/input/events) for details about changing or preventing an input value.

### Search.Autocomplete and Search.Panel

Use `onType` to receive query changes and load suggestions. Use `onChange` to handle a confirmed result, and `onSelect` to follow the active result during keyboard navigation.

`onSubmit` handles Enter when no result is active or selected. Selecting a result keeps the query by default.

With `mode="async"`, use `updateData` when results arrive and `showNoOptionsItem` when the search returns no results. `showIndicator` displays loading inside the input without opening an empty panel. Clearing an asynchronous query should clear the data, hide loading, and ignore any pending response.

<PropertiesTable props={AutocompleteEvents} />

The callbacks also provide methods such as `updateData`, `showIndicator`, `hideIndicator`, and `setHidden`. Search.Panel also passes `close` to its children render function for custom actions that close the surface. See [Autocomplete events](/web/components/autocomplete/events) and [dynamically changing data](/web/components/autocomplete/events#dynamically-change-data).
