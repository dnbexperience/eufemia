## Properties

### Shared properties

These properties apply to `Search.Input`, `Search.Autocomplete`, and `Search.Panel`. All default to `size="medium"`, `labelSrOnly`, and `showClearButton`. A custom `submitElement` or `showSubmitButton` replaces the shortcut hint.

<PropertiesTable props={SearchProperties} />

### Search.Input

Supports [Input properties](/web/components/input/properties) and [events](/web/components/input/properties#events). It defaults to `type="search"` with a loupe icon. Use `value` to update the query, `ref` to access the input, `onChange` for query changes, and `onSubmit` for submission.

### Search.Autocomplete

Supports [Autocomplete properties](/web/components/autocomplete/properties) and [events](/web/components/autocomplete/properties#events). It also defaults to `preventSelection`, `keepValue`, `noScrollAnimation`, and `showAll={false}`, so filtered results do not end with an item that lists every option. With `mode="async"`, it defaults to `search={{ filter: false }}` and shows every result as provided, since the source has already filtered them. Other `search` options are kept. Use `inputValue` to update the query, `inputRef` to access the input, `onType` for query changes, and `onChange` for result selection.

### Search.Panel

Supports the same Autocomplete properties and events as `Search.Autocomplete`, including the `showAll` and asynchronous `search` defaults, with `openOnFocus` enabled by default. It owns `inline`, `resultsRender`, `skipPortal`, and `preventClose` to compose the results inside the panel. Keyboard navigation keeps visible results in place and smoothly scrolls results into view at the edge. Scrolling respects reduced motion; use `noScrollAnimation` to disable it. Use `popoverProps` for the supported surface options.

## Events

Search components use the events of their underlying components. All support `onFocus`, `onBlur`, `onClear`, and `onSubmit`.

### Search.Input events

Use `onChange` to receive query changes and `onSubmit` to handle Enter. Both receive an object containing `value` and `event`.

Inside a form, Enter also submits the form, as in any native search input. Call `event.preventDefault()` in `onSubmit` to handle the query without submitting the form. Search.Autocomplete and Search.Panel do not submit a surrounding form.

<PropertiesTable props={InputEvents} />

See [Input events](/web/components/input/properties#events) for details about changing or preventing an input value.

### Search.Autocomplete and Search.Panel events

Use `onType` to receive query changes and load suggestions. Use `onChange` to handle a confirmed result, and `onSelect` to follow the active result during keyboard navigation.

`onSubmit` handles Enter when no result is active or selected. Selecting a result keeps the query by default.

With `mode="async"`, use `updateData` when results arrive and `showNoOptionsItem` when the search returns no results. `showIndicator` displays loading inside the input without opening an empty panel. Clearing an asynchronous query should clear the data, hide loading, and ignore any pending response.

<PropertiesTable props={AutocompleteEvents} />

The callbacks also provide methods such as `updateData`, `showIndicator`, `hideIndicator`, and `setHidden`. Search.Panel also passes `close` to its children render function for custom actions that close the surface. See [Autocomplete events](/web/components/autocomplete/properties#events) and [dynamically changing data](/web/components/autocomplete/properties#dynamically-change-data).
