## Overview

`Field.Name` is a wrapper component for the [input of strings](/web/forms/base-fields/String), with user experience tailored for first name, last name and company names.

There is a corresponding [Value.Name](/web/forms/Value/Name) component.

```jsx
import { Field, Form } from '@dnb/eufemia/extensions/forms'

function MyForm() {
  return (
    <Form.Handler>
      <Field.Name />
      <Field.Name.First value="Nora" />
      <Field.Name.Last value="Mørk" />
      <Field.Name.Company value="DNB" />
    </Form.Handler>
  )
}
```

### Import

```tsx
import { Field } from '@dnb/eufemia/extensions/forms'
render(<Field.Name />)
render(<Field.Name.First />)
render(<Field.Name.Last />)
render(<Field.Name.Company />)
```

### Validation rules

#### Personal names

`Field.Name`, `Field.Name.First` and `Field.Name.Last` accept Unicode letters with their combining marks. A single straight apostrophe (`'`), curly apostrophe (`’`), hyphen or space can separate letters. For example, `O'Connor`, `O’Connor` and `Anne-Marie` pass. `Anne- Marie` does not. Digits and periods do not pass the default check.

A final `é` can be one character or an `e` followed by a combining accent. Both pass. The field does not normalize the spelling it submits. It still trims leading and trailing whitespace on blur by default.

#### Company names

`Field.Name.Company` has a separate pattern. A company name must start and end with a letter or number. It can contain punctuation and spaces inside. Two adjacent spaces or hyphens (including one of each), or two consecutive periods, do not pass.

### Autofill and length

| Field                | HTML `autocomplete` | Default `minLength` |
| -------------------- | ------------------- | ------------------- |
| `Field.Name`         | `name`              | 1                   |
| `Field.Name.First`   | `given-name`        | 1                   |
| `Field.Name.Last`    | `family-name`       | 1                   |
| `Field.Name.Company` | `organization`      | 3                   |

### Validators

The built-in pattern runs on blur and on submit. By default, it runs **before** your `onBlurValidator`. A callback can reject a name that passes the pattern. It cannot accept a name the pattern rejects. For example, a company callback can require a particular suffix without having to check `companyValidator` again.

For a personal-name field, set `onBlurValidatorMode="replace"` when the product needs a different pattern. The callback then decides which spellings to accept. It can still use `validators.nameValidator`. This example also accepts an initial followed by a period:

```tsx
import { Field } from '@dnb/eufemia/extensions/forms'
import type { NameValidator } from '@dnb/eufemia/extensions/forms/Field/Name'

const allowInitial: NameValidator = (value, { validators }) => {
  if (value && /^\p{L}\p{M}*\.$/u.test(value)) {
    return
  }
  return [validators.nameValidator]
}

render(
  <Field.Name.First
    required
    onBlurValidatorMode="replace"
    onBlurValidator={allowInitial}
  />
)
```

Without a callback, `replace` keeps the built-in pattern. `onBlurValidator={false}` turns off the blur validator; it does not supply a replacement rule. Required and length checks are separate from the blur validator. `Field.Name.Company` keeps its built-in-first behavior and exposes `validators.companyValidator`.

### Choosing a product policy

The default is an input aid, not a test of someone's identity or of whether a name is legal. Confirm restrictions with the service that stores or matches the name. A narrower policy can reject someone's spelling. An untested wider policy can let someone complete the form only to be rejected by that service.

The exported `personalNamePattern` is the current default. If your product policy fits a regular expression, use the `pattern` prop with `onBlurValidator={false}`. This uses `Field.String` pattern validation instead of the built-in blur check. For example, a service that needs the exact previous rules can still use the unchanged `namePattern` export:

```tsx
import { Field } from '@dnb/eufemia/extensions/forms'
import { namePattern } from '@dnb/eufemia/extensions/forms/Field/Name'

render(
  <Field.Name.Last
    required
    pattern={namePattern}
    onBlurValidator={false}
    errorMessages={{
      'Field.errorPattern':
        'Use the name format required by the registration service.',
    }}
  />
)
```

This preserves the old pattern's distinction between a final precomposed letter and a final combining mark. Use that policy only if the service requires it. Localize any product-specific instructions.

### Test your form

- Type or paste both apostrophe spellings and both representations of `José`. Submit the form and compare the saved value with the exact input, not just its appearance.
- Leave a required name empty, submit, then correct it using only the keyboard. With a screen reader, check that you can identify the field, understand its error and submit the correction.
- Test a name that your service accepts but the default pattern does not. Also test a name your service rejects. Check the full journey, including storage and retrieval.
