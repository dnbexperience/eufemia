Build your first accessible interface with Eufemia. This guide covers installation, imports, component events, and the conventions you need to continue.

## Installation

Install Eufemia with React and React DOM using your project's package manager:

```bash
npm i @dnb/eufemia react react-dom
# or
yarn add @dnb/eufemia react react-dom
# or
pnpm add @dnb/eufemia react react-dom
```

Import styles once in your application entry. The default import includes the DNB theme, components, and Forms styles:

```tsx
import '@dnb/eufemia/style'
```

For other brands, scoped styles, or smaller CSS bundles, see [CSS setup and structure](/web/styling-and-themes/css/). Check [requirements and browser support](/web/get-started/requirements/) before choosing your application setup.

## Render a component

```tsx
import { Button } from '@dnb/eufemia'

export default function App() {
  return (
    <Button text="Hello Eufemia" onClick={() => console.log('clicked')} />
  )
}
```

## Imports and TypeScript

The default package uses ESM and supports tree shaking. Import components, elements, and their TypeScript types from the public package. Import Forms and icons from their own entries:

```tsx
import { Button, Input, H1, P, Flex } from '@dnb/eufemia'
import { Form, Field, Value, Wizard } from '@dnb/eufemia/extensions/forms'
import { bell_medium } from '@dnb/eufemia/icons'
```

You can also use component entries such as `@dnb/eufemia/components/button`. See [module formats, SSR, and bundles](/web/ai-tools-and-resources/module-formats/) for CommonJS, server rendering, or scripts without an application build.

## How given props are merged

Eufemia components apply the props you give them on top of the ones they set themselves, either directly or through a prop object such as `closeButtonProps`. When you set the same prop as the component, the two are combined instead of yours replacing the component's:

- An event handler is called together with the component's own handler for the same event, so the component keeps doing what it does. A `Drawer` still closes, and a `Wizard.NextButton` still moves to the next step.
- A `className` is added to the component's own classes.
- A `style` is merged with the component's own, where your values win.
- For every other prop, your value wins. Avoid setting what the component controls itself, and use the property it offers for it instead.

To keep a component from doing what it normally does, use the property it offers for that, such as [`preventClose`](/web/components/drawer/properties/) on a `Drawer`, or the `preventNavigation` function that [`onStepChange`](/web/forms/Wizard/Container/events/) gives you on a `Wizard.Container`.

Fields in [Eufemia Forms](/web/forms/) merge the same way. See [how given attributes are merged](/web/forms/about-fields/#how-given-attributes-are-merged) for what that means for a field's value and validation.

## Interaction states

Components provide hover, active, focus, and disabled states. Use their documented properties and theme tokens rather than reproducing those states in application CSS.

## Before you build

1. Choose a [brand and color scheme](/web/styling-and-themes/brands-and-dark-mode/).
2. Use [Forms](/web/forms/) for data input, validation, and read-only values. Start with [Build your first form](/web/forms/getting-started/).
3. Use [Wizard](/web/forms/Wizard/) for journeys with several steps.
4. Plan [loading states](/web/components/skeleton/) and [localization](/web/styling-and-themes/configuration/localization/).
5. Choose [global or isolated styles](/web/styling-and-themes/css/style-isolation/) for the application around Eufemia.

## Key conventions

- Use [Flex](/web/layout-and-typography/layout/flex/), [Space](/web/layout-and-typography/layout/space/), and the [spacing system](/web/layout-and-typography/spacing/) for consistent layout.
- Prefer `Field.*` for user input, `Value.*` for read-only content, and [HTML elements](/web/layout-and-typography/elements/) for semantic text.
- Use [semantic tokens](/web/styling-and-themes/design-tokens/) and [typography helpers](/web/layout-and-typography/typography/css-reference/) before adding custom values.
- Keep [keyboard focus, labels, and error messages accessible](/web/accessibility/).
- Test browser zoom, enlarged default fonts, narrow layouts, and the devices you support. Use `rem` for scalable dimensions.
- Reuse [shared utilities](/web/ai-tools-and-resources/utilities/) for common behavior.

## Forms essentials

- [Form.Handler](/web/forms/Form/Handler/) handles submission and validation. [GlobalStatus](/web/components/global-status/) can summarize errors.
- Use [Form.Outlet](/web/forms/Form/Outlet/) with a shared `formHandlerId` when a field or form control lives outside the handler subtree.
- Use [Form.Section](/web/forms/Form/Section/) for edit and view modes.
- Most fields have a matching value component. [Value.SummaryList](/web/forms/Value/SummaryList/) builds a read-only summary.
- Use Zod or [AJV JSON Schema](/web/forms/Connectors/) when validation comes from a schema.

## AI instructions and skills

Eufemia's documentation is optimized for AI assistance. When generating or reviewing code, use the following sources in order of priority.

- Use the documentation exactly as provided.
- Gather all required information from the documentation before using it as a reference.
- Do not make assumptions or infer missing details unless explicitly instructed to do so.

### Versioned documentation (preferred)

1. Install `@dnb/eufemia` with the package manager used in your project (e.g., npm, yarn, pnpm).
2. Find where `node_modules` is located in your project.
3. Read docs from `node_modules/@dnb/eufemia/docs/web/usage/first-steps/quick-reference.md`.
4. Follow relative links between markdown files.
5. Use this content as the primary reference.

### Non-versioned documentation
