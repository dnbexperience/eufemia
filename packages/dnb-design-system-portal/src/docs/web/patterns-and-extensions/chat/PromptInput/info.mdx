## Import

```tsx
import { PromptInput } from '@dnb/eufemia/extensions/chat'
import '@dnb/eufemia/extensions/chat/style'
render(<PromptInput />)
```

## Description

`Chat.PromptInput` is where the user writes a message. On desktop, Enter sends the message and Shift+Enter adds a new line. On touch-primary devices (`hover: none` and `pointer: coarse`), Enter adds a new line; use the send button to submit. Set `isBusy` while a reply is pending or streaming. With `onStop`, the send button becomes a stop button. Pressing empty space on the card focuses the textarea with the caret at the end. Custom controls and context content keep their own interactions. After sending, focus returns to the textarea. Stopping also returns keyboard focus when the empty compact input removes the stop button.

Use `variant="compact"` for a single line on a welcome screen. It shows the Aino icon by default and hides the send button until the user enters text. While busy, the stop button stays available even when the input is empty. Use `icon` to change the leading icon or `icon={null}` to hide it. For human chats, hide it or choose an appropriate icon rather than identifying the sender as Aino.

The default variant is flat and gains a shadow when the textarea is focused. The card uses Textarea hover and focus border colors and thickness; its toolbar buttons retain their own focus styles. The compact variant has a shadow by default; set `dropShadow={false}` for an inline surface or `dropShadow` to elevate the default variant. Keyboard focus remains visible in both variants.

With `disabled`, the card uses Textarea's disabled background and border tokens. Set `textareaProps.status` for error feedback; the card keeps its error border while the textarea is focused.

Pass context chips as `children` to show attachments or references above the input. The context area opens and closes with HeightAnimation, including its spacing. Your application owns their data and removal actions. Use controls with `type="button"` so removing context does not submit the message.

## Composing custom controls

Use `startActions` to place controls on the left of the toolbar, or before the textarea in the compact variant. Use `endActions` to place controls before the built-in Send or Stop button. Both accept React content, including multiple buttons, a menu or a custom component. Their DOM order follows the visual order for keyboard navigation.

Compose actions with [Button](/web/components/button), [Dropdown](/web/components/dropdown) or your own controls. PromptInput does not provide attachment or microphone buttons because their behavior and labels belong to the application. For icon-only buttons, provide a translated `aria-label` and a tooltip. Use `type="button"` on custom buttons to avoid submitting the message.

`disabled` applies to the textarea and built-in Send or Stop button. Pass the same disabled state to custom controls when they should also be unavailable. PromptInput does not change the properties of custom content. Keep controls concise in the compact variant; use the default variant or move additional actions into a menu when space is limited.
