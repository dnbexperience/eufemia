> **Note:** There is no `v12` release. The version `v12` was accidentally published to NPM and has since been removed. Because a published version number cannot be safely reused, `v12` has been skipped entirely, and these breaking changes are released as `v13` instead.

## Migration

v13 of @dnb/eufemia contains _breaking changes_. Follow the migration steps below for removed APIs and changed behavior. The [deprecations](#deprecations) section lists APIs that remain available for compatibility and can be replaced separately.

## Install

To upgrade to @dnb/eufemia v13 with NPM, use:

```bash
$ npm i @dnb/eufemia@13
# or
$ yarn add @dnb/eufemia@13
```

## CSS custom properties

### Design-token color migration

The design-token color update changes the meaning of `--token-color-background-neutral-alternative` in DNB and Eiendom and removes 13 foundation CSS custom properties. Applications must review direct references, including Tailwind utilities and values in JavaScript/TypeScript strings.

For text backgrounds, usually replace `--token-color-background-neutral-alternative` with `--token-color-background-neutral-subtle`. For UI fills such as progress tracks, usually use `--token-color-background-neutral-base`. Check contrast and nested surfaces in every supported theme and color mode; this is not a blanket find-and-replace.

See [Migrating information and neutral colors](/web/styling-and-themes/design-tokens/colors#migrating-information-and-neutral-colors) for the before/after values, removed-variable inventory and application checklist. Follow that guidance when upgrading to the release containing this update, even if you are not upgrading to v13.

### Typography: \{#css-custom-properties-typography\}

- Replace `--sb-font-size-*` with `--font-size-*`
- Replace `--sb-font-size-medium--plus` with `--font-size-medium`
- Replace `--sb-line-height-*` with `--line-height-*`

The font size and line height values now come from Figma brand tokens. Existing CSS variable names remain available.

The generated JavaScript `properties` exports keep their existing value format: concrete `rem` values for the size scale and aliases for `lead`.

The deprecated Sbanken-prefixed properties are still emitted. Their values differ from the generic scale, so check the rendered result when replacing them.

#### Tailwind

- Replace `--text-sb-*` with `--text-*`
- Replace `--text-sb-medium--plus` with `--text-medium`
- Replace `--leading-sb-*` with `--leading-*`

## Keyboard focus styling

The [keyboard focus guidance](/web/accessibility/focus/#keyboard-focus-styling) now uses a 3px blue outline with a 2px transparent gap, without changing text, icon, or background colors. Input fields keep their field focus styles. Explicit dark surfaces (`surface="dark"`) keep their previous focus styles to preserve contrast. Lists, tables, cards, and similar layouts use no gap, and hover styling takes precedence while focused.

For new and updated custom styles, use `--token-color-stroke-action-focus` with `--focus-outline-width` (`0.1875rem`) and `--focus-outline-offset` (`0.125rem`), or the [focusOutline()](/web/ai-tools-and-resources/utilities/sass/#keyboard-focus) Sass helper. Layouts use a 3px blue edge: pass `$offset: 0` without an existing edge, or overlap a 1px border or inset shadow with `$offset: -0.0625rem` and replace its color with the focus token. Use `$width: 0.125rem` (2px) if a scroll container's existing spacing would clip 3px. Remove focus-only text, icon, and background color overrides when adopting the outline.

`--focus-ring-width` remains `0.25rem`. The existing focus color tokens, `focusRing()`, `focusStyle()`, and focus helper classes remain available with their current behavior. No replacement is required to upgrade to v13. Migrate each usage individually; do not reduce the legacy width globally. Eufemia component updates will follow in separate changes.

## Print styles

The `dnb-print` scope now prints pure black text, borders and form
outlines on white paper and removes descendant CSS backgrounds. Previously
this paper appearance required `dnb-print--plain`. Remove the redundant
modifier from existing markup:

```diff
-<article class="dnb-print dnb-print--plain">
+<article class="dnb-print">
```

Existing markup with both classes still works. Screen colors, typography
and wrapper layout remain unchanged. If you relied on `dnb-print` to retain
brand colors when printing, use your own print styles outside this scope.
See [print styles](/web/styling-and-themes/css/document-styles/#print-styles).

## Component changes

### [Theme](/web/styling-and-themes/brands-and-dark-mode/theme)

The deprecated `name` property and `data-name` attribute have been removed. Use `brand` and `data-brand` instead.

```diff
-<Theme name="carnegie">
+<Theme brand="carnegie">
```

Replace `useTheme().name` with `useTheme().brand`. For persisted theme state, replace `getTheme().name` and `setTheme({ name })` with `getTheme().brand` and `setTheme({ brand })`.

`VisibilityByTheme` also matches on the theme object, so replace `name` there too:

```diff
-<VisibilityByTheme visible={[{ name: 'sbanken' }]}>
+<VisibilityByTheme visible={[{ brand: 'sbanken' }]}>
```

With `name` removed, TypeScript reports it as an unknown property here. Plain JavaScript gets no such warning — the filter simply stops matching, and the content silently disappears.

The deprecated `size` property, `ThemeSizes` type, `data-size` attribute, and `eufemia-theme__size--*` CSS classes have also been removed. Use `density`, `ThemeDensities`, `data-density`, and `eufemia-theme__density--*` instead.

```diff
-<Theme size="basis">
+<Theme density="basis">
```

The deprecated `VisibilityByTheme.Name` component has been removed. Use `VisibilityByTheme.Brand` instead.

```diff
-<VisibilityByTheme.Name />
+<VisibilityByTheme.Brand />
```

### [SidebarMenu](/web/patterns-and-extensions/sidebar-menu/)

Replace `breakpoint` with `drawerAt` on `SidebarMenu.ResponsiveProvider`. The deprecated `breakpoint` alias is removed in v13.

`SidebarMenu.Header` now uses `text` for its label and `children` for the nested menu items. Move the previous label children to `text`. The deprecated, no-effect `headingLevel` compatibility property is removed in v13 because Header is a visual menu label rather than a semantic page heading.

```diff
-<SidebarMenu.Header headingLevel={3}>Accounts</SidebarMenu.Header>
+<SidebarMenu.Header text="Accounts">
+  <SidebarMenu.Item id="overview" text="Overview" />
+</SidebarMenu.Header>
```

### [Flex](/web/layout-and-typography/layout/flex/)

Flex now uses native CSS gap and renders React children unchanged. The [legacy compatibility APIs](#flex-compatibility-apis) remain available during migration.

#### Custom components

The `_supportsSpacingProps` marker is no longer needed. A custom component becomes a flex item through its rendered root, so nothing needs to opt it in to the layout. When the component should accept [spacing properties](/web/layout-and-typography/layout/space/), apply them to its root with `useSpacing` so an author can still adjust the spacing per instance.

**Before (v11):**

```tsx
import { clsx } from 'clsx'
import { useSpacing } from '@dnb/eufemia/components/space/SpacingUtils'

function MyComponent({ className, ...props }) {
  const params = useSpacing(props, {
    ...props,
    className: clsx('my-component', className),
  })

  return <div {...params} />
}

// Opted the component in to receive spacing from Flex.Container.
MyComponent._supportsSpacingProps = true
```

**After (v13):**

```tsx
import { clsx } from 'clsx'
import { useSpacing } from '@dnb/eufemia/components/space/SpacingUtils'

function MyComponent({ className, ...props }) {
  const params = useSpacing(props, {
    ...props,
    className: clsx('my-component', className),
  })

  return <div {...params} />
}
```

For a component that already applied spacing to its root, deleting the marker is the only change. The rendered `<div>` is now a flex item automatically, and `useSpacing` keeps the component's own `top`, `right`, `bottom`, and `left` props working — in CSS mode those values participate in pairwise spacing and may replace the adjacent container gap. If a component did not previously apply spacing to its root, adopt `useSpacing` as shown so authors can keep adjusting spacing per instance. A component that never needs per-instance spacing can simply drop the marker and receive the container gap.

#### Wrapper components

`Flex.withChildren` remains available as a deprecated compatibility adapter. It never hoisted a wrapper's children into the outer container's flex line. When the HOC marked a wrapper, `Flex.Container` automatically injected a nested `Flex.Container` inside the wrapper's root, inheriting the outer container's props, and laid the wrapper's children out there. The rendered DOM was already outer container → wrapper root → inner container. To keep that layout without the adapter, render the inner `Flex.Container` yourself.

**Before (v11):**

```tsx
import { Flex } from '@dnb/eufemia'

// The HOC marked the wrapper, so Flex.Container injected a nested
// Flex.Container inside it to lay out the wrapper's children.
const Wrapper = Flex.withChildren(({ children }) => <div>{children}</div>)

render(
  <Flex.Container direction="vertical">
    <Item />
    <Wrapper>
      <Item />
      <Item />
    </Wrapper>
    <Item />
  </Flex.Container>
)
```

**After (v13):**

```tsx
import { Flex } from '@dnb/eufemia'

// Render the inner Flex.Container yourself — this is the container
// the HOC used to inject automatically.
function Wrapper({ children }) {
  return (
    <div>
      <Flex.Container direction="vertical">{children}</Flex.Container>
    </div>
  )
}

render(
  <Flex.Container direction="vertical">
    <Item />
    <Wrapper>
      <Item />
      <Item />
    </Wrapper>
    <Item />
  </Flex.Container>
)
```

The DOM structure is unchanged from v11 — a wrapper root containing a nested `Flex.Container`. The only difference is that you now provide that inner container explicitly and set its own props (`direction`, `gap`, `divider`, …) instead of inheriting them from the outer container. If a wrapper renders no DOM of its own — for example a Fragment, a context provider, or another transparent component — its children already become direct flex items of the outer container and need no inner `Flex.Container`.

When using `divider="line"` or `divider="line-framed"`, the CSS engine paints the divider without rendering `<hr>` elements. This removes the corresponding separator roles from the accessibility tree. If a divider conveys semantic separation, render explicit `Hr` elements instead of relying on the `divider` property.

### [Accordion](/web/components/accordion/)

- Replace `id` with `connectedTo` on `Accordion.Content` when connecting to a standalone tertiary button.

### [DatePicker](/web/components/date-picker/)

- Remove `enableKeyboardNav`. It has no effect, because keyboard navigation in the calendar is always enabled.

### [Modal](/web/components/modal/), [Dialog](/web/components/dialog/) and [Drawer](/web/components/drawer/)

- Replace `closeButtonAttributes` with `closeButtonProps`.

```diff
-<Drawer closeButtonAttributes={{ text: 'Custom text' }} />
+<Drawer closeButtonProps={{ text: 'Custom text' }} />
```

- Replace `triggerAttributes` with `triggerProps`.

```diff
-<Dialog triggerAttributes={{ text: 'Open', variant: 'primary' }} />
+<Dialog triggerProps={{ text: 'Open', variant: 'primary' }} />
```

- The `ModalTriggerAttributes` type has been removed. Use `ButtonProps` from `@dnb/eufemia` instead.

### [InfoCard](/web/components/info-card/)

Replace InfoCard with `Card.Info` and compose its content as children. Card.Info supplies the card surface, shadow, and padding. See [Card.Info](/web/components/card/#cardinfo) for layout, sizing, interaction, and dismissal guidance.

Before:

```tsx
<InfoCard
  title="Savings tip"
  text="Save a little every month."
  acceptButtonText="Start saving"
  onAccept={onAccept}
/>
```

After:

```tsx
<Card.Info>
  <Flex.Stack gap="x-small">
    <P size="small" weight="medium">
      Savings tip
    </P>
    <P size="small">Save a little every month.</P>
  </Flex.Stack>
  <Button variant="secondary" onClick={onAccept}>
    Start saving
  </Button>
</Card.Info>
```

- Replace `text` with paragraph children. Use heading children or Card's `title` property for the title.
- Replace `icon`, `src`, `alt`, and `imgProps` with IconPrimary, Img, or other graphic children. Include appropriate alternative text.
- Replace accept and close button props, including the `*ButtonAttributes` aliases, with explicit Button children. For a top-corner close control, render `Card.Info.CloseButton` as a direct Card.Info child and pass the dismissal handler as `onClick`.
- Replace `centered` with your content layout, for example `Flex.Stack align="center"` and centered text. Wrap loading content in `Provider skeleton`.
- Remove `stretch` and control width through the containing layout. Other Card properties, including spacing and `dropShadow`, can be passed directly to Card.Info.

### [Popover](/web/components/popover/)

- Replace `triggerAttributes` with `triggerProps`.

```diff
-<Popover triggerAttributes={{ 'aria-haspopup': 'menu' }} />
+<Popover triggerProps={{ 'aria-haspopup': 'menu' }} />
```

- The `PopoverTriggerAttributes` type has been removed. Use `triggerProps` instead.

### [Typography](/web/layout-and-typography/typography/)

-<Typography.Provider/>

### Forms selection variants

[Field.Toggle](/web/forms/base-fields/Toggle/), [Field.Selection](/web/forms/base-fields/Selection/), and [Field.ArraySelection](/web/forms/base-fields/ArraySelection/) use Chip for their button variants. Existing variant names, values, validation, and help remain supported.

The controls have Chip's appearance and native checkbox or radio markup. Update custom CSS selectors and tests that target `.dnb-toggle-button` or button elements. Single selection uses one Tab stop and arrow keys; multiple selection uses independently focusable checkboxes.

 }

## Chat extension

The `Ai` extension is now named [Chat](/web/patterns-and-extensions/chat/) because the components support human-to-human conversations as well as AI experiences.

```diff
-import { Ai } from '@dnb/eufemia/extensions'
-import '@dnb/eufemia/extensions/ai/style'
+import { Chat } from '@dnb/eufemia/extensions'
+import '@dnb/eufemia/extensions/chat/style'
```

Replace `Ai.Message`, `Ai.Conversation` and other namespace uses with `Chat.*`. Named component imports move from `@dnb/eufemia/extensions/ai` to `@dnb/eufemia/extensions/chat`; public types use the `Chat` prefix, such as `ChatMessageProps`. The optional virtualization driver and isolated styles are also available under `extensions/chat/Virtualization` and `extensions/chat/style/isolated`.

**Ai remains available as a compatibility fallback for now.** Existing imports, `Ai*` types, locale imports and style entry points still use the same implementation. Existing `.dnb-ai-*` CSS classes and `--ai-*` custom properties remain unchanged. Documentation URLs redirect to Chat.

Use the `Chat` namespace for translation overrides. Legacy `Ai` overrides still work; `Chat` takes precedence for keys provided in both namespaces. The extension remains experimental. AI-specific features such as `aiGenerated` are still opt-in; use them only when they describe the content correctly.

## Deprecations

Deprecated APIs remain available for compatibility. Replacing them is recommended, but deprecation alone does not require a change to upgrade to v13. Removal is a separate breaking change and is documented explicitly.

### ToggleButton

ToggleButton and ToggleButton.Group are deprecated in favor of [Chip](/web/components/chip/). Existing imports, styles, and behavior remain available. Migration is recommended for new or updated interfaces, but is not required to upgrade to v13. No removal version is scheduled.

```diff
-import { ToggleButton } from '@dnb/eufemia'
+import { Chip } from '@dnb/eufemia'

-<ToggleButton.Group multiselect values={['savings']}>
-  <ToggleButton value="savings" text="Savings" />
-  <ToggleButton value="funds" text="Funds" />
-</ToggleButton.Group>
+<Chip.Group selectionMode="multiple" values={['savings']}>
+  <Chip value="savings">Savings</Chip>
+  <Chip value="funds">Funds</Chip>
+</Chip.Group>
```

Single selection remains the default. Set `value` on Chip.Group for single selection and `values` for multiple selection. Move initial selection from a child's `checked` to its group. Standalone chips still use `checked`.

Use `text` or `children` for the option name and Chip.Group's `label` for the group label. Chip's `labelSrOnly` hides the option name; the group property hides the group label. Replace `leftComponent` with `icon` for decorative content. Evaluate custom icon placement and size against Chip's leading icon layout. Keep interactive help in `suffix`, outside the selectable chip. Replace function children with their rendered React content.

Use string or number identifiers instead of object or array values. Match option and group value types, and keep identifiers unique after conversion to strings. Change events preserve the identifier type. Chip.Group returns `values` in both selection modes and `value` identifies the changed option.

Chip renders native inputs, except for addable chips outside single selection groups, which use native toggle buttons with `aria-pressed`. Update refs, event target assumptions, CSS selectors, and tests that depend on ToggleButton's button markup. Selected, enabled options in Chip.Group participate in native form submission. Set `name` on Chip.Group to choose the submitted field name; otherwise a generated name is used. Radio groups use one Tab stop and arrow keys; multiple selection uses independently focusable checkboxes or addable toggle buttons. `variant` controls appearance independently of selection mode.

See [Chip's API differences](/web/components/chip/#toggle-buttons) and [examples](/web/components/chip/demos/).

### Flex compatibility APIs

The following deprecated APIs remain available during migration:

- `Flex.withChildren`
- `_supportsSpacingProps`
- `wrapChildrenInSpace`
- `layoutEngine="legacy"`

The previous child-inspection engine can still be selected explicitly:

```tsx
<Flex.Container layoutEngine="legacy">...</Flex.Container>
```

Avoid these APIs for new integrations. See the [Flex migration steps](#flex) and [Flex.Container migration guidance](/web/layout-and-typography/layout/flex/container/#backwards-compatibility) for alternatives.

### [Autocomplete](/web/components/autocomplete/)

The individual search-related props remain supported as deprecated aliases for the `search` object. Replace them when updating the component:

- `disableFilter` → `search.filter`
- `disableReorder` → `search.reorder`
- `disableHighlighting` → `search.highlight`
- `searchNumbers` → `search.numbers`
- `searchInWordIndex` → `search.matchInsideWordsFrom`
- `searchMatch` → `search.match`

Note that the `disable*` props invert, so a disabled feature becomes `false`:

```diff
-<Autocomplete
-  disableFilter
-  disableReorder
-  disableHighlighting
-  searchNumbers
-  searchInWordIndex={4}
-  searchMatch="starts-with"
-/>
+<Autocomplete
+  search={{
+    filter: false,
+    reorder: false,
+    highlight: false,
+    numbers: true,
+    matchInsideWordsFrom: 4,
+    match: 'starts-with',
+  }}
+/>
```

### [Img](/web/layout-and-typography/elements/image/)

- The `imgClass` alias is deprecated but still supported. Use `imageClassName` for new code.
- The `element` prop is deprecated and remains available. Keep the default `figure` wrapper and use `figureProps` to pass native properties to it.

```diff
-<Img src="image.png" alt="Description" imgClass="image-class" />
+<Img src="image.png" alt="Description" imageClassName="image-class" />
```

### [Provider](/web/styling-and-themes/configuration/provider/)

The top-level `currencyDisplay` property is deprecated and remains in the Provider types. It already had no effect on NumberFormat; this is not a v13 behavior change. To configure currency display, use `NumberFormat={{ currencyDisplay }}` instead.

```diff
-<Provider currencyDisplay="code">
+<Provider NumberFormat={{ currencyDisplay: 'code' }}>
```
