This is a compact, practical guide for teams who already know they want Eufemia and need the fastest path to decisions and common patterns.

## Before you build

1. **Choose the brand theme**:
   - `ui` (default), `sbanken`, `carnegie`, or `eiendom` ([theming](/web/usage/customisation/theming)).
2. **Form-heavy flow?**
   - Prefer the [Forms extension](/web/extensions/forms) and `Field.*` components for validation and structure.
3. **Multi-step journeys?**
   - Use [Wizard](/web/extensions/forms/Wizard) for step navigation and focus management.
4. **Loading states?**
   - Plan for [Skeleton](/web/components/skeleton) or [ProgressIndicator](/web/components/progress-indicator).
5. **Internationalization?**
   - Plan for [localization and i18n](/web/usage/customisation/localization).
6. **Styling strategy?**
   - Decide how to [import styles](/web/usage/customisation/styling/consume-styles) and whether you need [style isolation](/web/usage/customisation/styling/style-isolation).

## Key conventions

1. Prefer [Flex](/web/layout/flex) and [Forms](/web/extensions/forms) over other layout and form solutions.
2. Use `Field.*` components for user input and forms whenever available (all [fields](/web/extensions/forms/feature-fields/)).
3. Follow [accessibility basics](/web/usage/accessibility) and avoid font sizes below 14px.
4. Use the [spacing system](/web/layout/spacing) and [Space](/web/layout/space) instead of ad-hoc margins.
5. Import styles once at the app root (`import '@dnb/eufemia/style'`).
6. Prefer [helpers and tools](/web/helpers) over custom one-off utilities.
7. Use [HTML elements](/web/elements) for semantic structure, even when not using components.
8. Favor CSS custom properties and spacing helpers over hard-coded values ([Spacing](/web/layout/spacing), [Typography](/web/typography)).

## Forms essentials

- Start with [Getting started](/web/extensions/forms/getting-started) for forms patterns, validation, and data handling.
- Use [Form.Handler](/web/extensions/forms/Form/Handler) for submit/validation and [GlobalStatus](/web/components/global-status) for error summaries.
- For rendering fields or form UI outside the handler subtree, use [Form.Outlet](/web/extensions/forms/Form/Outlet) together with a shared form handler id (`formHandlerId`).
- For multi-step flows, use [Wizard](/web/extensions/forms/Wizard).
- For edit/view modes, use [Form.Section](/web/extensions/forms/Form/Section).
- Prefer [feature fields](/web/extensions/forms/feature-fields) (e.g. `Field.*`) when available.
- For read-only outputs, use [Value components](/web/extensions/forms/Value) (e.g. `Value.*`).
- Most `Field.*` components have a corresponding `Value.*` component; you can mix fields and values in the same form.
- For read-only summaries, use [Value.SummaryList](/web/extensions/forms/Value/SummaryList).
- Validation schemas can be provided via Zod or [AJV JSON Schema](/web/extensions/forms/Connectors).

## AI instructions and skills

Eufemia's documentation is optimized for AI assistance. When generating or reviewing code, use the following sources in order of priority.

- Use the documentation exactly as provided.
- Gather all required information from the documentation before using it as a reference.
- Do not make assumptions or infer missing details unless explicitly instructed to do so.

### Versioned documentation (preferred)

1. Install `@dnb/eufemia` with the package manager used in your project (e.g., npm, yarn, pnpm).
2. Find where `node_modules` is located in your project.
3. Read docs from `node_modules/@dnb/eufemia/docs/web/usage/first-steps/quick-reference.md`.
4. Follow relative links between markdown files.
5. Use this content as the primary reference.

### Non-versioned documentation

1. Fetch `https://eufemia.dnb.no/web/usage/first-steps/quick-reference.md`.
2. Read docs from the fetched markdown file.
3. Follow absolute URLs for referenced markdown files.
4. Use this content as a reference only.
